# 🚀 Деплой combined_bot — полностью бесплатно (1 Render free-сервис)

Это инструкция для запуска **5 ботов** в одном Render-сервисе. Решение полностью бесплатное — умещается в 750 бесплатных часов Render.

---

## 📊 Расчёт почему это бесплатно

| Параметр | Значение |
|----------|----------|
| Render free instance hours / мес | **750** |
| 1 сервис × 24 ч × 30 дн | **720 часов** |
| Запас | **+30 часов на холодные старты и редеплои** |
| Память (Render free) | 512 MB |
| Ожидаемое потребление | ~430 MB (launcher 30 MB + 5 ботов × ~80 MB) |

✅ **Хватает!** (но впритык по памяти — смотри совет ниже)

---

## 🎯 Схема работы

```
              GitHub (1 репозиторий: combined_bot)
                          ↓ autoDeploy
              Render.com (1 free Web Service, Docker)
                          ↓
              ┌─────────────────────────────────┐
              │ launcher.py (главный процесс)    │
              │   ├─ subprocess: bot A (8081)   │
              │   ├─ subprocess: bot B (8082)   │
              │   ├─ subprocess: bot C (8083)   │
              │   ├─ subprocess: bot D (8084)   │
              │   ├─ subprocess: bot E (8085)   │
              │   ├─ watchdog (рестарт упавших) │
              │   └─ HTTP /health на :8080     │
              └─────────────────────────────────┘
                          ↑
              cron-job.org (1 джоб: пинг /health каждые 10 мин)
```

### Шаг 6. Настрой cron-job.org (чтобы сервис не засыпал)

1. Зарегистрируйся на https://console.cron-job.org/ (если ещё нет аккаунта)
2. **Подтверди email** — без этого джобы не запускаются
3. **Create Cron Job** с параметрами:

   | Поле | Значение |
   |------|----------|
   | Title | `ping 5-bots-combined` |
   | URL | `https://5-bots-combined.onrender.com/health` |
   | Request Method | `GET` |
   | Execution Schedule | `Every 10 minute(s)` |
   | Request Timeout | `30` seconds |
   | Enable | ✅ |
   | Save Responses | ❌ |

5. Подожди 10-15 минут, зайди в cron-job.org → Dashboard

## 🆘 Если что-то не работает

### Health возвращает `"bots_running": 0` или меньше 4

1. Открой Render → сервис → вкладка **Logs**
2. Ищи строки с префиксами `[kras-news]`, `[krsk-vacancies]`, `[horoscope]`, `[ai-free]`
3. Частые проблемы:
   - `❌ Не задан TELEGRAM_BOT_TOKEN` → не ввёл `BOT_X_TOKEN` в Render dashboard
   - `Forbidden: bot is not a member of the channel chat` → бот не админ канала
   - `Chat not found` → неверный `BOT_X_CHANNEL` (должен начинаться с `-100...`)

### Telegram-бот не отвечает на /status

1. Открой `https://api.telegram.org/bot<ТОКЕН>/getMe` — должен вернуть JSON с инфо о боте
2. Если `409 Conflict` — где-то ещё запущен этот бот. Удали webhook:
   ```
   https://api.telegram.org/bot<ТОКЕН>/deleteWebhook?drop_pending_updates=true
   ```
3. Проверь, что твой `user_id` = `8430203469` (узнать у `@userinfobot`)
4. В Logs Render ищи ошибки приёма сообщений

### Сервис на Render не запускается

1. Render → сервис → вкладка **Events** или **Logs**
2. Частые ошибки:
   - `Build failed` → проблема в Dockerfile, смотри build logs
   - `Port binding error` → что-то уже слушает PORT, но наш launcher сам слушает 8080, должно работать
   - `Out of memory` → 4 бота не помещаются в 512 MB. Тогда либо отключи картинки (`ENABLE_IMAGES=false`), либо сократи `POSTS_PER_DAY`

### Cron-job показывает "failed"

1. Зайди в cron-job.org → конкретный джоб → History
2. Коды ответов:
   - `200` ✅ всё ок
   - `503` — `/health` вернул `bots_running < 4`, то есть какие-то боты упали
   - `502` / `503` сразу после деплоя — Render ещё просыпается (cold start), подожди 1-2 минуты
   - `000` — Render сервис остановлен. Запусти вручную через Render dashboard

### Боты работают, но не постят в канал

1. Проверь, что бот **админ канала** с правом публикации сообщений
2. Открой `https://api.telegram.org/bot<ТОКЕН>/getChat?chat_id=<CHANNEL_ID>` — должен вернуть инфо о канале
3. Если `Forbidden: bot is not a member` → добавь бота в канал как админа вручную

### Холодный старт

Render free после 15 минут простоя «засыпает». При следующем запросе — cold start ~30-50 секунд.
Cron-job.org каждые 10 минут пингает `/health`, поэтому сервис не успевает заснуть.
Но если ты сам заходишь на статус-страницу после долгого простоя — она может грузиться 30+ секунд. Это нормально.

## ⚠️ Лимиты, о которых нужно знать

### Render free-план

- **750 instance hours в месяц** на аккаунт
- 1 сервис × 24 ч × 30 дн = 720 часов → помещается
- Если будешь создавать **второй** сервис на этом же аккаунте — лимит быстро кончится
- Cold start: после 15 мин простоя сервис засыпает, при запросе просыпается 30-50 сек
- **Память: 512 MB RAM** — 5 ботов могут не поместиться если все включены картинки

### ⚠️ Если не хватает памяти (Out of Memory в логах)

На Render free 512 MB, и 5 ботов с включенными картинками могут упереться. Симптомы:
- В логах Render: `Container ran out of memory`
- Сервис рестартует каждые несколько минут
- Часть ботов не стартует

**Решения (выбери одно):**

1. **Отключить картинки у бота E** — в `launcher.py` в блоке `bot_e_ai_digest` добавь строку:
   ```python
   "ENABLE_IMAGES": "false",
   ```
   Это сэкономит ~30-50 MB RAM (бот E будет постить только текст).

2. **Отключить картинки у ботов A и D** — в `launcher.py`:
   ```python
   # в bot_a_krsk_news
   "ENABLE_IMAGES": "false",
   # в bot_d_ai_free
   "ENABLE_IMAGES": "false",
   ```

3. **Перенести бота E в отдельный Render-сервис** (если очень нужен AI Дайджест с картинками)

### cron-job.org

- Бесплатный план: неограниченное количество джобов
- Минимальный интервал: 1 минута
- Запросы не выполняются если email не подтверждён

### Groq API

- Бесплатный план: 30 запросов/мин, 14400 запросов/день
- 5 ботов × ~5 постов/день × 1 запрос на саммари = ~25 запросов/день → сильно ниже лимита
- Ключ один на все 5 ботов

### Telegram Bot API

- Лимит 30 сообщений в секунду, 20 сообщений в минуту в один чат
- Боты постят редко (3-8 постов/день), лимиты не трогаем
